Overview

L0 单模块 Bench，评价每页 Slide 对应的讲稿与 action 序列是否可解析、忠于页面内容、具有教学价值，并在正确时机引用或操作页面元素；不评价整门课程的跨页 Journey。

existing architecture

#594 已形成生产数据抽样、Promptfoo 回放、确定性格式检查与 LLM Judge 两层结构；#903 进一步沉淀可复制脚本、Promptfoo 配置、Rubric v2、报告和 Slide 101 例双模型实验，但 PR 已关闭且未合并，接入时需迁回有效资产。

Dataset Design

可从 676,501 条生产索引按 FIRST/MIDDLE/LAST 分层抽样。现有 Calibration50 用于 Judge 校准，#903 的 Slide 集包含 101 个唯一场景；首轮先复核并去重这些案例，再确定 Pilot Dataset 版本。

rubric and metrics

确定性层检查产品解析格式、原始格式、segment 数和 element ID；质量层采用 protocol、fidelity、teaching、action。Rubric v2 已增加动作滥用惩罚、教学深度和无标签角色模拟检查，弱化单页场景不适合判断的 discussion 要求。

historical evidence

Calibration50 和 #903 双模型结果证明方法可运行，但人工复核曾发现 Judge 横向不一致、部分 API 错误和单页讨论维度失真；旧结果仅作校准证据，不进入当前排名。

current status and next gate

当前只展示 Bench 卡片和设计说明，暂无可比较 Entry。下一步恢复 #903 有效资产，补 benchmark.json 与 adapter，重跑失败 Case 和当前候选模型，完成人工校准后发布 Pilot 排名。
