Overview

评估底层模型在真实 OpenMAIC 课堂运行链路中，能否理解用户当前意图、生成准确且有效的教学回应，并以受控的 Agent 协作和课堂动作完成交付。本页结果执行于已被替换的旧课堂 Agent 链路；当前线上已切换至 Pi 底座，因此 Legacy 结果仅供历史参考。

What This Benchmark Measures

每个 Case 提供一条课堂用户输入，以及当时的课程阶段、Agent 角色、场景和会话配置。候选模型通过真实 OpenMAIC 课堂链路生成完整响应，包括多轮 Agent 发言和课堂动作。本 Bench 评价这一次课堂响应是否真正解决用户问题并形成可用的教学交付；不评价整门课程的跨页连贯性，也不把尚未运行的 Stress 诊断或 Pi Chat A/B 结果混入当前排名。

Dataset Design

  • 当前榜单使用固定的历史 Core50 快照：30 个 Core Case 覆盖常规、清晰的课堂任务，20 个 Boundary Case 覆盖歧义、纠错质疑、节奏与格式调整、多约束或协作风险等更难交互。
  • Case 来自真实课堂场景，覆盖解释与问答、课堂控制、课程续讲、纠错、格式要求和上下文承接；Comparison Group 以 Dataset SHA 固定本次实际题集。
  • 完整 v1 设计包含 100 个主质量 Case（70 Core + 30 Boundary）和 10 个单独报告的 Stress Case；当前页面只展示其中历史 Core50 的 Pilot 结果。

Methodology

  1. 01使用同一组 Core50 Case，通过 OpenMAIC 共用 runAgentLoop 和真实 /api/chat 路径执行候选模型。
  2. 02Harness 保存完整课堂执行，包括 assistant messages、课堂动作、运行状态和延时；目标模型执行与评分相互独立。
  3. 03GPT-5.6 读取用户请求、课堂上下文和完整执行记录，使用同一份 v3.1 Rubric 分别评估五个质量维度。
  4. 04每个 Case 只对适用维度计分，再按维度权重汇总 Overall Quality；Judge 在本次 350 次评分中无错误。
  5. 05有非空内容的 timeout 按实际交付结果继续评分，同时保留执行失败；空输出等不可评分失败不虚构质量 0 分。

五个质量维度先按 0–4 评分，再换算为页面上的 0–100 表达；执行稳定性单独展示，不直接合成质量 0 分。

Key Insights

  • 课堂交付是共同短板：七个模型的 Classroom Delivery 都低于各自的 Agent Coordination，说明“组织了合理角色”并不等于“及时、稳定地完成了课堂交付”。
  • DeepSeek V4 Pro 与 Kimi K2.7 Code 的 Overall 分别为 76.22 和 75.58，当前精度不足以说明明显质量差异；但 Target Failure Rate 分别为 14% 和 32%，运行稳定性差距明显。
  • Gemini 3 Flash Preview 的 Content Quality 为 73.75，在七个模型中最高；Overall 只有 68.58，主要受 Agent Coordination 67.25 和 Classroom Delivery 54.00 拖累，说明内容能力与课堂编排能力需要分开判断。
  • Kimi K2.6 的 Target Failure Rate 达 90%，Overall 也只有 42.46；其 45 次失败均留下非空 partial output 并被按实际交付评分，因此低分不是把 timeout 机械记为 0 的结果。

Known Limitations

  • 当前是 Core50 Pilot，只覆盖完整 110 Case 设计中的 30 Core + 20 Boundary；未运行剩余主质量 Case，也不包含 10 个 Stress Case。
  • 350 次执行中有 239 次完整结束、100 次非空 partial timeout 进入质量评分、11 次不可评分失败被排除；不同模型的质量分母并不完全相同。
  • 当前榜单固定使用 inclass-rubric/v3.1-human-calibrated；Bench 代码的最新默认 Rubric 已是 v3.2-handoff-calibrated，新旧结果不能直接混排。
  • Dataset 仍是 machine-curated Pilot，尚未完成逐条具名人工审核；Rubric 经过人工校准不等于 Dataset 已正式晋级。
  • 结果复用了历史目标模型执行，模型别名不能证明供应商底层版本始终不变；延时也只能解释当时的运行条件，不能当作当前线上 SLA。
