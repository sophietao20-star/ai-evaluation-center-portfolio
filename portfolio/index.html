01 · Problem

评测结果很多，真正可用的决策链路很少

各 Benchmark 输出格式不同，新结果需要人工整理。
模型、Deployment 与 Thinking 缺少稳定版本身份。
质量、成功率、Token 与延迟没有统一展示口径。
运行结果直接上榜，缺少审核、撤榜和历史审计。

02 · Product Scope

从看榜，扩展到持续评测与受控发版

模型选型

能力总榜、场景榜、单 Benchmark 排名与覆盖率并列呈现；质量、成功率、Token 和延迟保持独立口径。

持续评测

统一管理候选模型和 Benchmark 版本，复用原生 Runner，通过 Adapter 收敛不同结果格式。

受控发版

Viewer 只消费 Published Entry；Publisher 负责运行、审核、发布、撤榜与恢复。

结果追溯

榜单结论可追到 Run、Result 和 Artifact；发布状态作为独立事件记录，不覆盖历史事实。

03 · Operating Loop

新增候选到正式结论的五步闭环

操作状态与评测事实分开：Run / Result / Artifact 保留原始证据，Entry 与 Publication Event 管理榜单状态。

01

登记

版本化登记 Model、Deployment、Thinking 与 Benchmark。

02

执行

选择 Model × Benchmark，运行兼容性、Smoke 与正式评测。

03

审核

核对质量、失败样本、Token、Latency 与运行证据。

04

发布

Draft 经人工确认后进入正式榜单；导入成功不会自动发榜。

05

治理

支持撤榜、恢复与追加式审计，底层运行证据保持不变。

04 · Architecture

独立应用，复用评测与身份基础设施

产品层保持独立边界；底层不重造 Runner。结构化对象进入 PostgreSQL，大型证据进入 OSS，页面和 API 使用同一套角色门禁。
